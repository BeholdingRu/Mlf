# MLF — трекер ежедневных задач

Веб-кабинет: регистрация по email, ежедневные задачи, статистика за неделю / месяц / всё время, блок веса и шкала «% формирования привычки». Данные хранятся в Supabase.

## 1. Проект в Supabase

1. Создайте проект на [supabase.com](https://supabase.com).
2. В **SQL Editor** выполните файл `supabase/schema.sql`.
3. В **Authentication → Providers → Email** включите вход по email и паролю.
4. Для сценария «забыли пароль» с **6-значным кодом**:
   - **Authentication → Email Templates → Reset password**
    - В шаблоне должен быть токен, не только ссылка, например: `Ваш код: {{ .Token }}`
    - Сохраните шаблон и проверьте, что письма уходят (для тестов удобен Inbucket в локальном стеке или реальный SMTP).

Регистрация не требует дополнительного кода доступа. Если база раньше использовала такое
ограничение, один раз выполните `supabase/remove_registration_access.sql` в **SQL Editor**.
Перед добавлением формы регистрации также проверьте, что создание новых пользователей разрешено
в настройках Supabase Authentication.

Если база уже была создана ранее, для каталога продуктов отдельно выполните
`supabase/add_saved_products.sql` в **SQL Editor**.

Чтобы добавить категории к уже сохранённым продуктам, после обновления приложения выполните
`supabase/add_saved_product_categories.sql` в **SQL Editor**. Все существующие продукты будут
перенесены в категорию «Мясо и мясные продукты».

Чтобы добавить флаг «Избранное» к существующему каталогу, также выполните
`supabase/add_saved_product_favorites.sql` в **SQL Editor**.

Чтобы сохранять составленные приёмы пищи в подвкладке «Меню», для существующей базы выполните
`supabase/add_saved_meals.sql` в **SQL Editor**. Приёмы пищи связаны с каталогом «Продукты»,
поэтому изменения КБЖУ продукта автоматически отображаются и в меню.

Чтобы сохранять БЖУ в новых записях потребления, выполните для существующей базы
`supabase/add_daily_food_log_nutrition.sql` в **SQL Editor** после `supabase/add_saved_product_nutrition.sql`.
БЖУ старых записей будут взяты из одноимённых продуктов личного каталога.

Чтобы добавить белки, жиры и углеводы к существующим продуктам, выполните
`supabase/add_saved_product_nutrition.sql` в **SQL Editor**. Для уже сохранённых продуктов
значения будут установлены в `0`; их можно заполнить через редактирование продукта.

Чтобы добавить выбор часового пояса и автоматический центровой город для расчёта времени заката,
выполните или повторно выполните `supabase/add_profile_location.sql` в **SQL Editor**.

Чтобы новые профили по умолчанию использовали тему «Ретро» и «Стиль 1», для существующей базы
один раз выполните `supabase/set_default_appearance.sql` в **SQL Editor**. Настройки уже
существующих пользователей этот скрипт не изменяет.

Чтобы сохранять подтверждения дней в разделе «Путь → С.Ш.», выполните
`supabase/add_path_day_confirmations.sql` в **SQL Editor**.

Чтобы сохранять завершённые уроки в разделе «Путь → Школа Шалом», выполните
`supabase/add_course_lesson_completions.sql` в **SQL Editor**.

Чтобы сохранять личные заметки в разделе «Путь → Практикум осознанности», выполните
`supabase/add_mindfulness_notes.sql` в **SQL Editor**.
Для категорий заметок и переноса существующих заметок в «Неотсортированные» после этого выполните
`supabase/add_mindfulness_note_categories.sql`.

Чтобы добавить настройку «Ежегодный цикл» в блоке Шаббата для существующей базы, выполните
`supabase/add_annual_cycle_setting.sql` в **SQL Editor**.

Чтобы добавить флаг «Удвоить объём» для упражнений в существующей базе, выполните
`supabase/add_double_exercise_volume.sql` в **SQL Editor**.

Чтобы задача питания использовала итоговую норму каждого дня на момент 00:00 и последующие
изменения нормы не меняли прошлые результаты, выполните
`supabase/add_calorie_norm_history.sql` в **SQL Editor**. Этот же файл можно выполнять повторно
после обновлений; он также добавляет администраторское исправление нормы для отдельных прошлых дат.

Чтобы связать стандартные задачи «Телостроительство:Питание» и «Чтение Библии» и сохранять
дневную цель чтения, выполните `supabase/add_default_tasks.sql` в **SQL Editor**.
Первые пять открытых глав по-прежнему сохраняются для дерева в Supabase; главы сверх этого
предела учитываются только локально в текущем браузере.

### Синодальный перевод Библии

Для таблицы с текстом стихов выполните `supabase/add_synodal_bible.sql` в **SQL Editor**.
Затем задайте `SUPABASE_SERVICE_ROLE_KEY` только в локальном окружении и запустите:

```
node scripts/import-synodal-bible.mjs
```

Импортёр использует открытый набор `open-bibles` (66 книг, 31 352 стиха) и сохраняет только
текст стихов — без комментариев, примечаний и параллельных мест. Серверный ключ нельзя добавлять
в клиентский код или коммитить.

## 2. Ключи приложения

В каталоге `web` скопируйте `.env.example` в `.env`:

```
VITE_SUPABASE_URL=https://xxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJ...
```

URL и anon-ключ: **Project Settings → API**.

## 3. Запуск

Нужен Node.js 20+.

```
cd web
npm install
npm run dev
```

Откройте адрес, который выведет Vite (обычно http://localhost:5173).

## Как устроен кабинет

- **Ежедневные задачи** — отметка один раз в сутки, пункт становится зелёным. Справа шкала привычки: число дней с отметкой / дни из настроек.
- **Неделя** — с понедельника по сегодня, процент = отметки / число прошедших дней недели.
- **Месяц** — с 1-го числа текущего месяца, процент считается так же.
- **Всё время** — сколько дней задача была отмечена.
- **Вес** включается в настройках: слева показывается `значение из настроек > сегодняшняя цифра`. Сегодняшнюю цифру можно ввести, нажав на блок (не чаще раза в сутки; повтор в тот же день заменяет значение). Счётчик дней стартует с даты первой записи веса в настройках.
- **Настройки** (справа сверху) — задачи: добавить, переименовать, удалить, задать дни до 100% шкалы; блок веса: показ и исходная цифра.
